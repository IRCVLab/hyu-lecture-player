# HYU Lecture Player Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** A visible browser player for both courses, initially weeks 1 and 2, reusable for later weeks.

**Architecture:** Node/Playwright CLI, persistent private browser profile, DOM-based course adapter, pure selection functions, sequential playback controller. Reuse authentication knowledge from HYU-course-registration without executing its application.

**Tech Stack:** Node 24, Playwright, Chrome, node:test.

### Task 1: Inspect live LMS
- [ ] Inspect actual authentication, course inventory, weekly structure, player frames and progress UI.
- [ ] Record only nonsecret structural findings; resolve exact probability/statistics course.

### Task 2: Selection and CLI
Files: package.json, selection.mjs, tests/selection.test.mjs, courses.json.
- [ ] Write failing tests for explicit weeks, current date selection, missing/ambiguous schedule, and excluding completed/nonvideo entries.
- [ ] Run `node --test tests/selection.test.mjs`, confirm missing behavior, then implement and rerun.

### Task 3: Browser adapter and playback
Files: browser.mjs, player.mjs, tests/player.test.mjs.
- [ ] Test sequential transitions on local video ended events, stall failure, and unverified completion.
- [ ] Implement authentication with protected local credentials and persistent profile, inventory reading, normal playback, bounded waits and progress verification based on observed LMS structure.
- [ ] Verify with `node --test` and real LMS inventory/playback. Never infer LMS completion solely from elapsed wall time.

### Task 4: Handoff
Files: run.sh, README.md, .gitignore.
- [ ] Provide one-command visible execution and --weeks 1 2 / --list.
- [ ] Run full tests, launcher --help and live --list; review implementation and document known limitations.
- [ ] Run requested initial queue and inspect live state, transitions and final LMS progress; claim only what is verified.
